写通道波形

浅色竖条是 VALID & READY 同时为高的那一拍，也就是真正发生握手的位置。 AWREADY 拉低的那几拍就是从设备在插等待，WVALID 全程不掉 —— 这正是 AXI 的核心规则： VALID 一旦拉起，在 READY 到来前不许撤销。

读通道波形

每次 RREADY 被拉低就是主设备在反压，从设备必须把 RDATA / RLAST 稳住不动 —— checker 的 AXI-R-STABLE 规则盯的就是这个，注入「等待期改数据」的 bug 会在这里被抓。

APB 两段式时序

每个传输固定是 SETUP（PSEL=1、PENABLE=0，正好一拍）→ ACCESS（PENABLE=1，等 PREADY）。 浅绿底是 SETUP，浅黄底是 ACCESS 里的等待拍。等待期间 PADDR / PWRITE / PWDATA 一个都不能变。

为什么这条表最重要：一个从不报错的 checker 和一个不存在的 checker 在干净回归里表现完全一样。 只有把 bug 注进去、并且期望它命中的是那一条规则（而不是碰巧被别的规则捎带抓走），才能说明断言是真的在工作。 比如「APB 等待期改地址」如果只比较相邻两拍就抓不到 —— 注入的实现是把地址整体偏移后保持住， 必须以上一拍 SETUP 的地址为基准全程比对才行。
